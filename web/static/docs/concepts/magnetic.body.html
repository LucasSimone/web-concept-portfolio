Magnetic

The element leans toward the cursor as it comes near, as if pulled by a magnet, and springs back when the cursor moves away. The pull fades in over a band around the element, so it starts moving before the cursor arrives and never jumps as the cursor crosses its edge. It rides a spring, so it eases in, overshoots a little and wobbles back to rest. How the pull is drawn is up to your CSS: by default it's a translate, but it can just as well be a tilt, a swell or a shadow.

Install

<script src="magnetic.js"></script>

Injects its own <style> tag with two rules (the translate and the depth rule), so no companion CSS file is needed.

Quick Start

<button class="magnetic-el">Get started</button>
<script src="magnetic.js"></script>

Every .magnetic-el on the page is set up on load. Data attributes change that per element: 

<button class="magnetic-el" data-magnetic-strength="0.5">★</button>
<div class="magnetic-el" data-magnetic-radius="120">Wide reach</div>

The attributes are data-magnetic-strength, -radius, -stiffness, -damping and -area. They win over options passed to initAll. To set options for a group of elements in code: 

Magnetic.initAll('.nav-icon', { strength: 0.5, radius: 40 });

Run that as a plain script straight after magnetic.js, before the page finishes loading: once auto-init has claimed an element, initAll skips it. To change one that's already set up, use Magnetic.get(el).update(options).

The Pull

The element heads for strength times the cursor's offset from its center. At the default 0.35, a cursor 100px right of center pulls it 35px right. The pull is at full strength anywhere over the element and fades to nothing across a band radius px wide around it, so the further out the cursor is, the weaker the pull.

The element doesn't jump to that point. A spring carries it there: stiffness is how hard the spring pulls and damping is its friction. Low damping overshoots and wobbles before settling; high damping settles with no bounce. A stiffer spring needs more damping to stop wobbling.

area measures the pull against another element instead of the element itself: an element, or a selector matched with closest() from the magnetic element. A small icon in a large button can then react to the whole button. 

<a class="card">
  <span class="magnetic-el" data-magnetic-area=".card" data-magnetic-radius="0">→</span>
  Read more
</a>

Neighbours

Elements close together share the cursor without colliding, by two rules. Only one element pulls at a time: of every element within reach, the one the cursor is nearest. The rest head back to rest, so two buttons side by side never both lean into the gap between them, and moving across hands the pull from one to the other. And an element reaches the cursor but never passes it: with the cursor off to one side, its near edge stops where the cursor is, so it can't cross into its neighbour's space. With the cursor over two at once (one nested in the other), the smaller one pulls.

Depth

A child with data-magnetic-depth moves that many times as far as the element in total. 1 moves with it, 2 twice as far, 0 stays where it is. Giving layers different depths makes them seem to float above one another. 

<div class="magnetic-el card">
  <span data-magnetic-depth="2.5">◆</span>
  <h3 data-magnetic-depth="1.6">Title</h3>
  <p>Body copy moves with the card.</p>
</div>

Inline elements ignore transform, so give a depth child display: inline-block or block. A child added after the element was set up needs an update() call to pick up its depth.

Styling

Every frame writes three custom properties onto the element. They are plain numbers, with no unit, so CSS can multiply them into whichever unit it needs: * 1px to move, * 1deg to tilt.

  • --magnetic-x, --magnetic-y: the current pull, in px.
  • --magnetic-amount: 0 to 1, how engaged the element is. 1 with the cursor over it (or its area), fading to 0 at the outer edge of radius.

The injected rule turns the first two into translate(calc(var(--magnetic-x) * 1px), calc(var(--magnetic-y) * 1px)). It's wrapped in :where(), so it has no specificity and any transform of your own replaces it: 

/* Tilt toward the cursor instead of moving. */
.tilt {
  transform: perspective(400px)
    rotateY(calc(var(--magnetic-x) * 1deg))
    rotateX(calc(var(--magnetic-y) * -1deg));
}

/* Move and swell. */
.swell {
  transform:
    translate(calc(var(--magnetic-x) * 1px), calc(var(--magnetic-y) * 1px))
    scale(calc(1 + var(--magnetic-amount) * 0.12));
}

/* Stay put, and cast a shadow away from the cursor. */
.shadow {
  transform: none;
  box-shadow: calc(var(--magnetic-x) * -0.6px)
    calc(var(--magnetic-y) * -0.6px) 0 #000;
}

The variables are inherited, so children can use them too.

Recipes

Icon buttons in a toolbar

Small targets can take a stronger pull and a shorter reach, so neighbours don't all move at once. 

Magnetic.initAll('.toolbar button', { strength: 0.5, radius: 24 });

A heavy, lazy pull

<button class="magnetic-el"
        data-magnetic-stiffness="60"
        data-magnetic-damping="12"
        data-magnetic-radius="140">Drag me along</button>

Only the label moves

Hold the element still and give the translate to a child instead. The variables are inherited, so the child can read them directly. 

.send { transform: none; }
.send span {
  display: inline-block;
  transform: translate(calc(var(--magnetic-x) * 1px), calc(var(--magnetic-y) * 1px));
}

Options

OptionDefaultDescription
strength0.35How far the element moves toward the cursor, as a share of the cursor's offset from its center. 1 would put its center under the cursor
radius60Width in px of the band around the element (or its area) where the pull fades in. 0 pulls only while the cursor is over it
stiffness220How hard the spring pulls toward its target. Higher is quicker and tighter
damping16The spring's friction. Lower overshoots and wobbles more
areanullAn element, or a selector matched with closest(), to measure the pull against instead of the element itself. See The Pull

Notes

Every magnetic element on a page shares one pointer listener and one animation loop. The loop runs only while an element is moving or the cursor is within reach of one, and stops the rest of the time. While the cursor is within reach it re-measures every frame, so an element that moves under a still cursor (in a carousel, say) keeps tracking it.

Only a hovering pointer (a mouse or a pen) pulls. A touch has no hover between taps, so on a touchscreen elements stay at rest. Keyboard focus doesn't move anything either.

Respects prefers-reduced-motion: under it auto-init skips every element, so nothing moves. Calling initAll yourself still sets elements up. The demo page does, so the effect can be tried there. The demo page edits strength, radius, stiffness and damping, and leaves alone any of them an element sets with its own data attribute.
