Concept · Hover

Liftoff

Hold the pointer over an element for a sustained dwell (default 1.5s) and it breaks contact with the page: rising into a slow ambient float while an underglow burns beneath it, somewhere between a car's underglow and a rocket's exhaust plume. Leaving before the dwell completes cancels cleanly with no visible motion at all; leaving after liftoff eases the element back down and lets the glow fade out. Injects its own shadow/glow layers behind whatever content you put inside the element, so applying the class and calling the script is the whole setup.

Install

<script src="liftoff.js"></script>

Injects its own <style> tag defining .liftoff-card and its shadow/glow layers, so no companion CSS file is required — but the host element needs its own size and content, since the injected CSS sets neither.

Quick Start

<div class="liftoff-card" style="width:300px;height:220px" tabindex="0">
  <h3>Liftoff</h3>
</div>
<script src="liftoff.js"></script>

Auto-initializes against every .liftoff-card element. tabindex="0" is optional but recommended — it makes the lift keyboard-triggerable via focus, not just pointer hover. To configure options: 

Liftoff.initAll('.liftoff-card', {
  dwell: 900,
  lift: 40,
});

Recipes

Rocket launch

A shorter dwell, faster rise, and a taller lift with more drift and tilt reads as an urgent, energetic launch rather than a gentle float. 

Liftoff.initAll('.liftoff-card', {
  dwell: 900, riseSmoothing: 160, lift: 46, driftX: 10, driftY: 14, tilt: 3.2, scale: 1.07,
  glowColor: '#ff5a1f', thrustColor: '#ffd23f',
});

Drone hover

A long dwell and slow, subtle drift/tilt reads as a heavier object holding a steady hover rather than lifting off. 

Liftoff.initAll('.liftoff-card', {
  dwell: 2200, riseSmoothing: 340, lift: 14, driftX: 3, driftY: 2, tilt: 0.6, scale: 1.015,
  shadowColor: '#0f172a', glowColor: '#38bdf8', thrustColor: '#60a5fa',
});

No contact shadow

shadowAtRest: false removes the dark contact shadow shown while the element rests on the page, independent of the glow above — useful over a background where a drawn shadow would look out of place. 

Liftoff.initAll('.liftoff-card', { shadowAtRest: false });

Lift with no glow

glow: false keeps the float/drift motion but drops the underglow and thrust plume entirely — just an element that quietly lifts. 

Liftoff.initAll('.liftoff-card', { glow: false });

Externally driven (no native hover)

hoverEvents: false skips binding the element's own pointer/focus listeners entirely, for cases where something else already owns hover detection for it — e.g. a carousel card whose own hover-follow slides it under a stationary cursor, which would otherwise retrigger native hover on its own (see every card on the homepage). Drive it with .enter() / .leave() instead. 

const [card] = Liftoff.initAll('.liftoff-card', { hoverEvents: false });
someExternalHoverSource.on('enter', () => card.enter());
someExternalHoverSource.on('leave', () => card.leave());

Options

OptionDefaultDescription

riseSmoothing220Time-constant (ms) easing toward fully lifted (or back down). Higher lags and settles more slowly; lower snaps closer to instantly
lift22Pixels the element rises at full liftoff
driftX7Pixels of ambient horizontal drift once lifted
driftY5Pixels of extra ambient vertical bob once lifted

Methods

MethodDescription
.enter()Starts the dwell timer toward liftoff, exactly like a real hover would. Called automatically by the bound listeners unless hoverEvents: false.
.leave()Cancels any pending dwell and eases back down, exactly like hover ending would.
.update(options)Merges new option values in — every value is read fresh each frame, so nothing needs to be rebuilt or restarted.
.destroy()Stops the animation loop, removes its bound listeners (if any), and removes the injected shadow/glow layers.
Liftoff.get(elOrSelector)Static lookup for an already-initialized instance, by element or selector.

Notes

Everything is driven by one continuous scalar per card (amount, 0–1) rather than a CSS class + transition: entry, the ambient float, and the settle-back all read the same value every frame, so a pointer leaving mid lift-in reverses smoothly from wherever it currently sits instead of snapping or fighting an in-flight CSS transition. Only mouse input triggers the dwell — touch/pen pointer events are ignored, since a sustained "hover" doesn't really exist on those. Respects prefers-reduced-motion by skipping auto-init entirely (an explicit Liftoff.initAll() call still works if you want it anyway). The demo page's own control panel adds a Profile dropdown with a few preset combinations (Underglow, Rocket Launch, Drone Hover, Homepage) as a starting point — picking one just sets the sliders below it, which stay freely editable afterward.
