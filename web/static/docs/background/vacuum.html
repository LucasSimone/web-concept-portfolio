Vacuum

A canvas overlay that sheds colored dust off whatever's inside the host element — text, images, borders, plain color panels — whenever the cursor gets close to it. Dust flies toward the live cursor position and fades out as it's pulled in. The real DOM content is never touched, hidden, or altered; the canvas sits on top of it with pointer events disabled, so it only ever draws the dust itself.

View Demo Download JS

Install

<script src="vacuum.js"></script>

Injects its own <style> tag for the canvas overlay, so no companion CSS file is required — but the host element needs its own height/content, since the injected CSS doesn't size it.

Usage

<section class="bg-vacuum">
  <h1>Some text</h1>
  <img src="photo.jpg" alt="">
</section>
<script src="vacuum.js"></script>

No text/data attribute needed — just apply the class to a container. A ResizeObserver and a debounced MutationObserver on the host rebuild the dust source points whenever the element resizes or its content changes. Auto-initializes against every .bg-vacuum element. To configure options: 

Vacuum.initAll('.bg-vacuum', {
  radius: 160,
  speed: 8,
});

Where dust comes from

On every rebuild, the whole subtree is scanned for four kinds of sources, each colored differently:

SourceColorHow points are placed
TextComputed color of the text's parent elementAlong each visual line box, via Range.getClientRects() — wrapped lines each get their own strip
BordersComputed border-*-color per sideAlong that side's edge, on any element with a visible border
<img> elementsActual pixel color, read from an offscreen canvasA grid across the image's rendered box, each point sampling its own nearest pixel — so different corners of the same image shed different colors
Solid backgroundsComputed background-colorA sparse grid across any element with a non-transparent background, including the host itself

An image from another origin without CORS headers taints the offscreen canvas and can't be read — it silently just won't shed any dust rather than sampling the wrong color.

Options

OptionDefaultDescription
radius110Distance from the cursor, in px, at which nearby points start shedding dust
density15Spacing in px between candidate points along text lines and borders
fillDensity22Spacing in px between candidate points across solid-background fills
imageStep8Spacing in px between sampled pixels across an image's rendered box
maxParticles300Concurrent particle cap, mostly a performance ceiling
particleSize2.5Particle diameter in px at full strength
speed2.5Base speed particles travel toward the cursor; accelerates as they get closer
spawnChance0.5Probability a given point sheds a particle once its cooldown has elapsed, scaled by proximity to the cursor
cooldown160Minimum time in ms a point must wait before shedding another particle

Notes

Points aren't consumed — a spot that's already shed dust can shed more once its cooldown passes, so hovering the same area repeatedly never runs it dry. Leaving the element doesn't cancel particles already in flight; they keep travelling to the last known cursor position and fade out there instead of freezing mid-air. Respects prefers-reduced-motion by skipping the animation loop entirely, so no dust sheds at all.
