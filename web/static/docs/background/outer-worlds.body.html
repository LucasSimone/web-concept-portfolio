Outer Worlds

A canvas showing a patch of a randomly generated planet. Moving the cursor across it turns the globe under your hand; letting go hands the motion to momentum, so the world keeps gliding and coasts back down to its own slow idle rotation. There is no edge to reach and no seam to cross — the terrain is 3D noise sampled on a sphere, so every point on the planet already has an elevation waiting to be asked for and you can keep panning in any direction forever. Purely decorative — it sits behind the element's content and never touches real page elements.

The same world draws in any of three styles, set by mode:

  • 'dots' — a halftone field. Open ocean is a faint lattice, coastlines dither in as the dots grow, and continental interiors and mountain chains close up into solid ink.
  • 'wire' — a mesh of parallels and meridians laid over the globe and pushed outward wherever it crosses land, so continents rise out of the grid as relief.
  • 'map' — the classic one: three flat inks and an outline. landColor fills the landmasses, borderColor draws the coastline around them, oceanColor is the sea they sit in. The coastline is a traced contour, not a stepped approximation, so it stays a smooth line at any zoom.

And in either of two projections, set by projection: 'globe' views the planet as a sphere, with the curvature that implies; 'flat' is an endless plane — no curvature, no poles, and no edge in any direction. Every style works in both, so there are six looks from one option pair. Note that scale means the same thing in each (the globe's radius in px), so a flat view usually wants a much lower one to cover a useful span.

A flat view is a different world from the globe, not the same one unrolled. Flattening a sphere leaves a top and a bottom where its poles were, and a map that should simply keep going cannot have those — so a flat view samples the generator's planar terrain instead of its spherical terrain. The seed drives both, but switching projection changes what is under you, the same way changing frequency does.

Install

<script src="outer-worlds.js"></script>

Injects its own <style> tag positioning the canvas behind the element's content, so no companion CSS file is required to render it — but the host element needs its own height/content, since the injected CSS doesn't size it. The downloaded file is self-contained: it carries the map generator (WorldMap) with it, so there is nothing else to fetch.

Quick Start

<section class="bg-outer-worlds" aria-label="Outer Worlds background"></section>
<script src="outer-worlds.js"></script>

No text/data attribute needed — just apply the class to a container with a size of its own. Every element gets its own planet from its own random seed. A ResizeObserver on the host element rebuilds the globe to fit, keeping the viewpoint you were already looking at. Auto-initializes against every .bg-outer-worlds element. To configure options: 

OuterWorlds.initAll('.bg-outer-worlds', {
  momentum: 2,
  dotSpacing: 9,
});

Recipes

Heavy world, long glide

A long momentum with a strong grab makes the planet feel massive: one pass of the cursor sends it turning for several seconds afterward. 

OuterWorlds.initAll('.bg-outer-worlds', {
  momentum: 2.6,
  sensitivity: 1.8,
});

Look, don't touch

interactive: false stops the cursor driving the world entirely, leaving it turning at autoSpin and nothing else. Worth reaching for behind text: a background that reacts to the pointer competes with whatever is being read on top of it. 

OuterWorlds.initAll('.bg-outer-worlds', {
  interactive: false,
  autoSpin: 1.5,
});

Fixed to the cursor

Drop momentum to 0 and the world stops the instant the cursor does, which reads as a map being dragged rather than a globe being spun. Pair it with autoSpin: 0 to leave the view exactly where it was left. 

OuterWorlds.initAll('.bg-outer-worlds', {
  momentum: 0,
  autoSpin: 0,
});

Wireframe instead of dots

mode: 'wire' swaps the halftone for a mesh. Nothing about the planet changes — the same seed gives the same world in either style, so the two can be switched between live. meshSpacing sets how far apart the lines sit and relief how far land lifts off the sphere. 

OuterWorlds.initAll('.bg-outer-worlds', {
  mode: 'wire',
  meshSpacing: 34,
  relief: 0.05,
});

A cartographer's globe

mode: 'map' fills the landmasses and draws a coastline around them. Give the three parts their own colors and it reads as an atlas plate; pull scale under 1 and the sea becomes the planet's own disc, horizon and all, with background as the space around it. 

OuterWorlds.initAll('.bg-outer-worlds', {
  mode: 'map',
  scale: 0.82,
  landColor: '239, 232, 216',
  borderColor: '20, 24, 28',
  oceanColor: '207, 223, 232',
  oceanAlpha: 1,
  fillAlpha: 1,
});

Leave borderColor and oceanColor unset and both borrow landColor, which with the default fillAlpha gives the one-color version: a light tint inside a crisp outline of the same ink.

A paper map

projection: 'flat' lays the world out on paper. There is no edge to reach in any direction and no pole to stop at: pan as far as you like, up, down or sideways, and the generator keeps producing terrain. Drop scale a long way, since it is still the globe's radius in px. 

OuterWorlds.initAll('.bg-outer-worlds', {
  mode: 'map',
  projection: 'flat',
  scale: 0.3,
  background: '#fbf7ef',
  oceanColor: '79, 125, 153',
});

A relief globe

Wireframe with the whole planet in frame and the relief pushed hard: continents stand off a fine mesh, and the lift fades out toward the limb so the silhouette stays a clean edge. 

OuterWorlds.initAll('.bg-outer-worlds', {
  mode: 'wire',
  scale: 0.78,
  dotSpacing: 8,
  meshSpacing: 26,
  relief: 0.09,
  autoSpin: 2.2,
});

The whole globe in frame

scale is the globe's radius as a multiple of half the element's diagonal, so at 1 the planet's limb touches the corners and anything lower brings the entire sphere into view with background showing around it. 

OuterWorlds.initAll('.bg-outer-worlds', {
  scale: 0.8,
  dotSpacing: 9,
});

An ocean planet, or a dry one

seaLevel is a threshold on an already-generated world rather than part of generating it, so it floods and drains the same planet instead of making a new one. Raise it for scattered islands, drop it to expose the ocean floor. 

OuterWorlds.initAll('.bg-outer-worlds', { seaLevel: 0.3 });

The same world every time

Pin the seed and the planet is reproducible: the same number always generates the same terrain, on every machine. 

OuterWorlds.initAll('.bg-outer-worlds', { seed: 20260928 });

Flat graphic continents

A short landRange reaches full-size dots just past the waterline, so landmasses read as solid shapes with a tight dither at the coast instead of a long halftone ramp across the interior. The cleanest-looking version of the dot style. 

OuterWorlds.initAll('.bg-outer-worlds', {
  landRange: 0.16,
  frequency: 1.6,
});

Color

landColor, oceanColor and background are independent, and every style uses the same set (borderColor joins them in Map). Leave oceanColor unset and the water borrows the land's ink, so a single color is enough until the parts should differ. oceanAlpha: 0 drops the open-water lattice entirely for a flatter look. 

OuterWorlds.initAll('.bg-outer-worlds', {
  mode: 'wire',
  background: '#0b0d12',
  landColor: '244, 244, 242',
  oceanColor: '111, 151, 180',
  oceanAlpha: 0.32,
});

projection'globe''globe' views the world as a sphere; 'flat' is an endless plane with no curvature, no poles and no edges. A flat view is a different world from the globe rather than the same one unrolled. scale means the same in both, so a flat view wants a much lower one
dotSpacing13Distance between sample points at the view centre, in px — the dot spacing in 'dots', the detail along each line in 'wire'. Also the resolution the world is generated at, so a finer spacing is a more detailed planet rather than a closer one. Floored per element at what one frame can afford to draw — roughly sqrt(width * height / 25000) px — so a very low value on a large element settles at that floor instead of asking for a million points a frame. Nearly all of the cost is rasterizing the samples rather than placing them, so this is the setting that decides what the effect costs on a slow device
scale1.25Globe radius as a multiple of half the element's diagonal, so it means the same at any aspect ratio. At 1 the planet's limb touches the corners; below that the whole globe comes into frame
interactivetrueWhether the cursor can turn the world. false leaves it to autoSpin alone — a background that moves but never reacts. momentum and sensitivity stop meaning anything when it is off
sensitivity1Fraction of the cursor's movement the world follows. At 1 the ground tracks the cursor exactly
momentum1.1Seconds of glide after the cursor stops — the time constant of the decay back to the idle spin, so roughly 3x this is how long a fling stays visibly in motion. 0 stops it almost immediately
autoSpin0.8Idle rotation in degrees of longitude per second, always eastward. 0 leaves the world still until the cursor touches it
maxLat78How far toward the poles the view can be pushed, in degrees. Globe only — a plane has no pole to stop at
seaLevel0.1Elevation that counts as the waterline. A threshold on an already-generated world, so changing it re-floods the same planet instead of generating another
landRange0.42Elevation above seaLevel at which land reaches full strength — full-size dots, or full relief. Wider keeps interior relief visible as texture instead of flooding to a solid mass; shorter gives flat graphic continents
meshSpacing34'wire' only: distance between mesh lines at the view centre, in px. Deliberately coarser than dotSpacing, which is the detail running along each line
relief0.05'wire' only: how far full-elevation land is pushed out from the sphere, as a fraction of the globe's radius. 0 lays the mesh flat on the surface
lineWidth1Stroke width in px of the ocean mesh in 'wire' and of the coastline in 'map'. Land mesh lines are drawn 1.4x heavier so coastlines carry weight
fillAlpha0.16'map' only: how solidly land is filled inside its coastline. Low values give the classic look — a light tint in a crisp outline, both from landColor. 1 fills land solid
oceanAlpha0.13Opacity of everything over open water — the lattice in 'dots', the mesh in 'wire', the flat sea wash in 'map' — which is what carries the rotation over empty ocean. 0 leaves the oceans blank
background'#ffffff'Canvas fill color drawn behind the world each frame
landColor'0, 0, 0'RGB triplet (no rgb() wrapper) for everything above the waterline
oceanColornullRGB triplet for open water, drawn at oceanAlpha. null reuses landColor
borderColornull'map' only: RGB triplet for the coastline drawn around each landmass, independent of the fill inside it. null reuses landColor
seednullWhich planet to generate. null picks a random one; any number is reproducible
frequency2.3How large the landmasses are. Low gives a few big continents, high breaks the world into archipelagos
octaves6Levels of terrain detail. Fewer is smoother and cheaper; more adds fine coastline structure
warp0.38How far the terrain is distorted before elevation is read — what turns round blobs into coastlines with peninsulas and bays. 0 disables it
ridge0.5Strength of the mountain-chain term added on land. 0 leaves the interiors smooth
landBias0Shifts the whole elevation field up (more land) or down (more ocean). Unlike seaLevel this regenerates the world

Methods

MethodDescription
.update(options)Merges new options in. A world-generating option (seed, frequency, octaves, warp, ridge, landBias) builds a new planet; dotSpacing, scale and relief rebuild the globe geometry; everything else — mode, the colors and seaLevel included — just applies on the next frame, so switching style or repainting mid-glide costs nothing and disturbs neither the world nor the viewpoint.
.newWorld(seed)Replaces the planet, keeping the current viewpoint and motion. Omit seed for a random one. Returns the seed actually used, so it can be stored and passed back later to get this world again.
.destroy()Stops the animation loop, disconnects the resize and visibility observers, removes the pointer listeners, and removes the canvas.
OuterWorlds.get(elOrSelector) / OuterWorlds.getAll(selector)Static lookups for already-initialized instances, by element/selector.

The map generator

The terrain itself is a standalone piece — WorldMap, bundled into outer-worlds.js and reusable on its own for anything else that wants procedural terrain. It samples seeded 3D gradient noise at points on a sphere, which is what buys the unbounded panning: longitude wraps at ±180° for free because both sides are literally the same point in 3D, the poles are ordinary points rather than stretched rows, and any coordinate can be asked for at any time without having generated its neighbours first. Everything is a pure function of the seed, so the same seed gives the same planet on every machine, in whatever order the points are requested. 

const world = new WorldMap({ seed: 1234, frequency: 2.3 });

world.heightAtLonLat(lon, lat);  // signed elevation; lon/lat in radians
world.heightAt(x, y, z);         // same, from a unit vector
world.heightAt2D(x, y);          // the same terrain on a flat plane
world.isLand(h);                 // h > seaLevel
world.landFactor(h);             // 0 at the coast, 1 landRange above it
world.reseed();                  // new planet in place, returns its seed

WorldMap.SphereLattice comes with it: an equal-area grid of points covering the whole sphere, each one's elevation sampled at most once and cached for the lattice's lifetime. Unlike a plain longitude/latitude grid it doesn't crowd points together at the poles, so coverage is uniform everywhere. It is what keeps this effect cheap — panning across the world pays for each point one time no matter how many frames it stays on screen. WorldMap.LonLatGrid is the other trade: plain longitude/latitude cells, which is what contour tracing's quad cells need. It stores nothing of its own and reads the lattice's cache, so either way there is one copy of the world in memory. WorldMap.PlaneGrid is the third, and the one every 'flat' view runs on: a square grid on an endless plane, drawn from the generator's planar sampling rather than its spherical one. Its row and column indices are plain signed integers with no range, so elevations live in a rolling window of slots addressed modulo its own size — panning re-uses every slot still in view and overwrites the ones that scrolled off, which is what keeps memory flat however far the map travels.

Notes

Pointer movement drives the viewpoint directly while the cursor is moving, so the ground tracks it exactly and the world feels grabbed rather than nudged; the moment it stops, the velocity it had built takes over and decays. Both halves are expressed as exponential decay over the frame's elapsed time and the position is integrated in closed form, so a glide covers exactly the same ground at 30fps as at 144, and a dropped frame doesn't produce a jump. Longitude wraps forever; latitude stops at maxLat short of the poles, where the view would otherwise flip over the top. Leaving the element does not stop the world — whatever momentum it was handed keeps carrying it, which is the point of throwing it. Respects prefers-reduced-motion by skipping the animation loop entirely: the world holds still, with no idle spin and no glide, and redraws only in response to the cursor. On touch, where there is no hover, the planet simply drifts at autoSpin; nothing about the effect competes with page scrolling.

The loop also stops when the element scrolls out of view, and picks up where it left off when it comes back — a screenful early, so it is already turning by the time it is looked at. This matters more than it sounds: requestAnimationFrame pauses itself for a hidden tab but not for an element that has merely scrolled past, so a background at the top of a long page would otherwise go on drawing every frame in full while the reader is far below it. On a phone that is the difference between a background and a battery drain.

In 'wire', the mesh is anchored to the world rather than the screen — parallels are lines of latitude, meridians lines of longitude — so it turns with the planet instead of sitting still in front of it. Two things follow from that and are handled for you. Relief fades out as the surface turns away from the viewer, because pushing a point off the sphere moves it across the screen by an amount that grows with its distance from the view centre; without that fade, highlands at the limb would fling out past the horizon as loose spikes. And the meridians thin by halves as they climb — every second one stops, then every second one of those — since they converge toward the pole and would otherwise pile into a solid starburst directly over it.

In 'flat' nothing is clamped or wrapped at all: the viewpoint keeps going in every direction, and elevations come from a rolling window of cells sized to the element rather than to the world, so travelling a long way costs no more memory than standing still. maxLat does not apply. Its terrain is also generated a few times larger than the globe's, because a flat view has to be zoomed well out to frame a useful span — at matching scale it would cross from sea to solid land inside a single cell, and since a flat grid is perfectly axis-aligned, those one-cell steps line up into straight vertical edges instead of a coastline. A flat view wants finer dotSpacing than a globe for the same reason.

The demo page's control panel adds a Profile dropdown with eight presets spanning the styles and both projections (Atlas, Wireframe, Relief Globe, Cartograph, Paper Map, Continents, Archipelago, Night Watch) as a starting point — picking one sets every control below it, which all stay freely editable afterward. Those presets also set landRange, which has no slider of its own; reach for it in code when the coast dither is too long or too abrupt.

Zoom, Detail and Mesh spacing are remembered separately for each projection there, since a flat view needs a much lower zoom and finer spacing than a globe to frame and draw the same sort of map — flipping View moves those three sliders to the values that view was last left at, rather than carrying one set across and landing badly in whichever direction it was flipped.

That panel only shows the controls that have something to act on: Mesh spacing and Relief appear for Wireframe, Land fill and Border color for Map, Background disappears for a flat Map (whose sea covers the canvas, leaving nothing behind it to tint), and Momentum and Grab strength disappear altogether once Pointer is switched off. The Pointer toggle is the one control a preset leaves alone — whether the cursor drives is a decision about the page the background sits on rather than about how the world looks, so it survives flipping through presets to compare them.
