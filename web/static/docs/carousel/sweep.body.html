Sweep

A strip of absolutely-positioned cards driven by wheel, drag, or pointer position. Unlike a normal slider, the focused card's own on-screen anchor sweeps across the viewport as you move through the list - flush against the left edge at the first card, centered at the midpoint, flush against the right edge at the last - and every card's width shrinks with distance from focus on an exponential curve, packed edge to edge so there's never a gap even as the strip compresses toward the background. Wheel/drag input tracks 1:1 with zero resistance while it's arriving; the moment it goes idle, a damped spring takes over and always settles exactly on a card.

Install

<script src="sweep.js"></script>

Depends on bindHoverDelegate for its pointer-follow tracking, and shares its per-tab position memory and its initAll/get/getAll surface with the other three carousels here - the downloaded file above already has both bundled in, so it's the one script tag above and nothing else. (Building from this repo's own source instead, those are shared/carousel-kit.js and shared/hover-delegate.js, loaded before sweep.js.) Injects its own <style> tag defining .sweep, .sweep-track, .sweep-line and .sweep-card, so no companion CSS file is required - but the host still supplies its own size and card chrome (width, height, border, background), the same as it would for any other element on the page.

Quick Start

<style>
  .my-sweep { height: 240px; }
  /* cqw = 1% of the strip's own width, so cards track the strip */
  .my-sweep .sweep-card { width: min(280px, 40cqw); height: 240px; }
</style>

<div class="sweep my-sweep">
  <div class="sweep-line" data-sweep-line="top"></div>
  <div class="sweep-line" data-sweep-line="bottom"></div>
  <div class="sweep-track">
    <div class="sweep-card">One</div>
    <div class="sweep-card">Two</div>
    <div class="sweep-card">Three</div>
  </div>
</div>
<script src="sweep.js"></script>

Auto-initializes against every .sweep:not(.is-empty) element. The two .sweep-line elements are optional guide rails placed at a distance-1 neighbor's height (skip them if you don't want the lines); every direct child of .sweep-track is treated as a card regardless of its own class, but .sweep-card is what the injected CSS positions - drop it and you're supplying that positioning yourself. To configure options: 

Sweep.initAll('.sweep', {
  cardStep: 260,
  friction: 0.7,
});

Recipes

Snappier or lazier

friction and snapStrength together shape the idle coast: friction is how much velocity decays each frame once input stops, snapStrength is how hard the constant pull toward the nearest card is folded in on top of that decay. High friction and high snap strength stop almost dead the instant you let go; low friction and low snap strength coast a long way and settle gently. 

// Stops almost immediately
Sweep.initAll('.sweep', { friction: 0.95, snapStrength: 0.09 });

// Coasts a long way before catching
Sweep.initAll('.sweep', { friction: 0.7, snapStrength: 0.02 });

How far a scroll/drag travels

cardStep is the pixels of wheel delta or drag distance that move the focus by exactly one card - lower reads as light and fast, higher as heavy, needing more input to cover the same ground. wheelSensitivity is a separate multiplier applied before that conversion, useful for tuning wheel and drag independently of each other since drag reads directly in pixels. 

Sweep.initAll('.sweep', { cardStep: 120, wheelSensitivity: 1.3 });

Turning off an input mode

hoverFollow and wheelEnabled each turn off one way of driving the strip, independently of each other and of card count - drag always stays live. Useful when something else on the page already owns the pointer or the wheel over that area (a page that scrolls its own content inside the strip, say), or when the pointer-chases-the-card motion just isn't wanted. 

// Wheel and drag only, no hover-follow
Sweep.initAll('.sweep', { hoverFollow: false });

// Drag and hover only - scrolling over the strip scrolls the page instead
Sweep.initAll('.sweep', { wheelEnabled: false });

Filtering the cards

There's no built-in filter UI - hide cards the normal way (a hidden attribute, or anything that removes them from layout) and call .refresh(). It re-reads which children are visible, recomputes the guide lines off whichever one is now first, and jumps back to card 0. 

const [instance] = Sweep.initAll('#mySweep');
document.getElementById('typeFilter').addEventListener('change', (e) => {
  document.querySelectorAll('.sweep-card').forEach((card) => {
    card.hidden = e.target.value !== 'all' && card.dataset.type !== e.target.value;
  });
  instance.refresh();
});

Moving it from your own code

Everything the wheel, a drag or the hover can do is on the instance as well, in two flavours: .step(), .next(), .prev(), .to(), .first() and .last() all travel there with the same spring the input modes use, while .jump() cuts straight to a card with no travel at all. .index and .length read back where it is. So a row of buttons, a keyboard shortcut of your own, or a strip driven entirely by something else on the page is wiring, not a fork. 

const strip = Sweep.get('#mySweep');

document.querySelector('.next').onclick = () => strip.next();
document.querySelector('.prev').onclick = () => strip.prev();
document.querySelector('.home').onclick = () => strip.first();

// No travel - straight there, as if it had always been on that card.
strip.jump(4);

Running itself

autoplay is milliseconds between automatic steps. It pauses itself while the pointer is over the strip, while it's off screen, in a background tab, and under prefers-reduced-motion - so a strip that runs itself still holds still for anyone actually reading it, with nothing to wire up.

A strip is the one carousel here with two real ends (the focus point itself sweeps from flush-left at the first card to flush-right at the last, which is a statement about ends), so it always reaches a last card eventually. autoplayEnd is what happens then: 'rewind' travels back through every card to the first, 'bounce' reverses and walks back a card per beat, 'jump' waits one beat and cuts back to the first, and 'stop' parks there - though even then the timer keeps running, so moving the strip off the end by hand has it pick up again. 

Sweep.initAll('.sweep', { autoplay: 2400, autoplayEnd: 'bounce' });

// Or drive the timer directly - the option stays as it was.
const strip = Sweep.get('#mySweep');
strip.pause();
strip.play();

Reacting to the focused card

Listen for the bubbling sweep-settle event instead of polling position - it fires on a card once it's actually at rest in the focus slot, not on every card passed through while moving, so it's the right hook for resetting a per-card preview animation whenever the visitor browses back to it. 

document.getElementById('mySweep').addEventListener('sweep-settle', (e) => {
  resetPreview(e.target);
});

An empty shelf before the first card

Add .is-empty and drop both .sweep-line elements - there's nothing yet to measure their height against. Auto-init skips anything matching .is-empty, so an empty shelf just sits there inert until a real card is dropped in and the class removed. 

<div class="sweep is-empty">
  <div class="sweep-track"></div>
  <p class="sweep-empty">Nothing here yet</p>
</div>

A tight stack instead of a shallow fan

minScale and scaleDecay together shape how quickly neighbors shrink away from the focused card. scaleDecay is the falloff rate per step of distance; minScale is the floor it falls toward. A low minScale with a high scaleDecay reads as a small focused card standing apart from a tightly packed, near-miniature stack behind it, rather than a shallow fan of similarly-sized neighbors. 

Sweep.initAll('.sweep', { minScale: 0.18, scaleDecay: 1.3 });

Methods

MethodDescription
new Sweep(root, options)Constructs directly against a root element carrying .sweep-track (used internally by initAll, and just as valid to call yourself).
.indexThe focused card's index, or -1 on an empty strip. A getter, not a setter - use .to() or .jump() to move.
.lengthHow many cards are in the strip (the visible ones, as of the last refresh()).
.step(direction, count)Moves count cards (default 1) in direction (1 forward, -1 back). A nudge to the settle spring rather than a queued move, so several in quick succession blend into one slide. Clamped at both ends.
.next(count) / .prev(count).step(1, count) and .step(-1, count).
.to(index)Brings index into focus, travelling there through the cards in between. An index past either end stops at that end - a strip has no loop for it to wrap round.
.first() / .last()The two ends, by the same travelling move .to() makes.
.jump(index)Puts index in focus at once, with no travel - the cut to .to()'s tracking shot. Still lands exactly on the card, so sweep-settle fires and the position is persisted just as it would be after a slide.
.play() / .pause()Start and stop the autoplay timer without touching the option. .pause() survives a later update(); .play() is what undoes it.
.playingWhether the timer is running - false after .pause(), for autoplay: 0, under reduced motion, and on a strip with fewer than two cards. It says nothing about whether a beat is currently being held back for a hovered or off-screen strip, which is a separate thing: that strip is still playing, just holding still.
.refresh()Re-reads which cards are currently visible (skips anything hidden), remeasures the guide lines, and jumps back to card 0 - call after changing which cards are shown.
.update(options)Merges new option values in - every positional option is read fresh each frame or event, and the autoplay timer is rebuilt.
.destroy()Stops the animation loop, clears the autoplay timer and removes every bound listener, including the hover delegate. The element stays marked as claimed, so a later initAll() skips it rather than re-initializing it.
Sweep.initAll(selector, options)Default selector '.sweep:not(.is-empty)'. Constructs an instance for each matching element not already claimed.
Sweep.get(elOrSelector)Static lookup for an already-initialized instance, by element or selector.
Sweep.getAll(selector)Every already-initialized instance matching a selector, default the same as initAll.

Events

EventDescription
sweep-settleBubbles from a card once it's actually at rest in the focus position - not fired on every card passed through while moving. event.target is the settled card.

Notes

The anchor sweeps, it isn't fixed to center: a normal centered carousel wastes the first and last card's own approach - half the track is empty space on either side just to let the end cards reach the middle. Here the focused card's anchor point instead sweeps between the two positions where a full-width card sits flush against the left or right edge of the track, linearly interpolated by how far through the list the current position is - so the strip uses its full width at every point in the browse, not just at the ends.

Packing is cumulative, not per-card: every card's on-screen center is the running sum of its own and every prior card's half-width (each already scaled by its own distance from focus), rather than a fixed slot width. That's what keeps cards packed edge to edge with zero gap as the strip compresses toward the background, at any scaleDecay. The continuous focus position - which sits between two integer cards while moving - interpolates those two cards' packed centers to find the point in the strip that should land on the anchor, then shifts the whole strip by the difference.

Two-phase input, not one continuous model: while wheel or drag input is actively arriving, position tracks it directly, 1:1, with zero resistance - what you scroll or drag is exactly what moves. The moment input goes idle (a short pause for wheel, pointerup for drag), a damped-spring coast takes over: the velocity already built up decays via friction while a constant pull toward the nearest card (snapStrength) is folded in, so it always ends up resting exactly on a card rather than wherever the input happened to stop.

Wheel capture respects the page's own scroll: wheel events are only captured (preventDefault) while there's room left to move in that direction - at either boundary the event is left alone, so scrolling past one that's already at its first or last card continues scrolling the page instead of trapping the cursor.

Hover drives focus too, above a card-count floor: while the pointer sits over a card (and nothing's being dragged or actively wheeled), that card becomes the settle spring's target instead of the nearest integer position - mousing across the strip pulls the focused card along with it the same way scrolling to it would. Below MIN_HOVER_FOLLOW_CARDS (5, not exposed as an option) this is disabled entirely: with only a couple of cards on screen, that tracking reads as fighting the pointer rather than helping navigate. Wheel and drag both stay live regardless of count.

Position is remembered per instance, per tab: the focused card's index is written to sessionStorage, keyed by the root element's own id (skipped entirely if it has none), every time a card settles. Navigating away to a card's own page and back restores that same card as focused instead of resetting to the first one - sessionStorage rather than localStorage so it fades once the tab or session ends. Restored only once, on an instance's first refresh() (the one the constructor itself triggers); a later refresh() call, e.g. from a type filter changing which cards are visible, always resets to card 0 instead.

A drag past the threshold suppresses the click: the track captures clicks (in the capture phase, ahead of a card's own link) and cancels them once a drag has moved past dragThreshold pixels - otherwise releasing a swipe on top of a card would also fire that card's own navigation. Below the threshold, a press-and-release in place still reaches the card normally.
