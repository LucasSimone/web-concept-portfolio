Text Effect · Scroll + Continuous + Hover

Rolodex

Splits a sentence into words and shows them one at a time on a fixed-size 3D card that flips to the next word — either a two-flap "split-flap" display or a single-card front/back flip — as the user scrolls, on a timed loop in continuous mode, or, in "static scroll" mode, by scrolling with the page held still while hovering it.

View Demo Download JS

Install

<script src="rolodex.js"></script>

Injects its own <style> tag covering the 3D card/flap/panel structure on first use, so no companion CSS file is required (the injected CSS hardcodes a white background on card faces). The downloaded file is self-contained - it bundles three small shared dependencies: hover-scroll-source.js ("static scroll" mode's wheel-target wiring), sequence-stepper.js (the animated-step engine behind 'continuous' driveMode and .next()/ .prev() below), and scroll-progress.js (the scroll-position math behind 'scroll' driveMode), all shared with Type Pan.

Usage

<div class="rolodex" data-text="Rolodex flips through words one by one">
  Rolodex flips through words one by one
</div>
<script src="rolodex.js"></script>

Reads data-text or trimmed textContent, splitting on whitespace into words. Auto-initializes against every .rolodex element — card size is measured via an offscreen canvas based on the widest word and computed font. To switch drive mode and configure options: 

Rolodex.initAll('.rolodex', {
  mode: 'split-flap',
  driveMode: 'continuous',
  flipWidth: 55,
  perspective: 900,
  shading: 0.05,
});

Options

OptionDefaultDescription
mode'split-flap'Visual style: 'split-flap' (two-flap card) or 'single-card' (simple front/back flip)
driveMode 'scroll'
  • 'scroll' — scroll position mapped across word segments
  • 'continuous' — self-animating hold/flip/rewind loop
  • 'hover' ("static scroll") — the element stays put on the page; wheel/trackpad input over it (or over an element tagged data-rolodex-hover="<that element's id>") drives the same scroll-position math as 'scroll' mode instead of scrolling the page
flipWidth55% of each word's segment spent mid-flip (the rest holds on a settled word)
perspective900CSS 3D perspective in px for the flip
shading0.550–1, how much a flap darkens as it turns edge-on
loopScrollfalseIn 'scroll'/'hover' driveMode only: makes the word list circular, so scrolling/wheeling past the last word flips straight on into the first (and past the first, back into the last) instead of stopping there. Independent of loop below - this is about active input continuing past the end, not what happens once input goes idle. Whatever feeds pushProgress() needs to pass values that aren't pre-clamped to 0–1 for this to have anything to work with (real page scroll can't - it's bounded by the page)
loopfalseIn 'scroll'/'hover' driveMode only: once input goes idle, keep flipping through the sentence on the same hold/flip/rollback clock 'continuous' mode uses (picking up from whichever word it was left on) instead of just holding there until input resumes
interval1400ms held on each word before flipping (continuous mode, or loop once idle)
flipDuration450ms spent mid-flip between words (continuous mode, or loop once idle)
rollbackSpeed900ms to rewind from the last word back to the first (continuous mode, or loop once idle)
hoverScrollDistance1000px-equivalent of wheel delta needed to sweep through the whole word list (hover mode)
scrollIdleDelay120ms of no scroll/wheel events before a fold-in-progress is treated as idle and settles instead of waiting for more input
snapStrength0.40–1, how fast the display catches up to scroll/hover position each frame - higher snaps almost instantly, lower lags behind and settles more slowly. Also governs the idle settle at the end of a fold. Try it live as "Catch-up speed" on the demo page.
stepPolicy 'redirect' What .next()/.prev()/.goTo() do if called again before the current flip lands - see the Methods section below.
  • 'redirect' — retargets immediately from wherever the flip visually is; a fast burst blurs past every word in between
  • 'rateLimit' — drops a call arriving less than minStepInterval after the last one accepted
  • 'queue' — lets the current flip finish, then plays queued calls back-to-back in order
minStepInterval450ms - only meaningful with stepPolicy: 'rateLimit'

Methods

.next() / .prev() flip forward or back one word; .goTo(wordIndex) flips directly to an arbitrary word, at the same per-word pace as a single flip (pass { duration } to use a fixed total time instead, regardless of distance). All three animate over flipDuration like a single 'continuous'-mode flip - never an instant jump - so a multi-word goTo() visibly flips through every word in between rather than blurring past them. Intended for 'scroll'/'hover' driveMode, the same scope as .pushProgress() below: scrolling or wheeling again immediately takes back over from wherever the flip landed. What happens if one of these is called again before the last one finished is governed by stepPolicy above - worth trying out on the demo page, which has a Next/Prev button and a live Step policy switch.

.remeasure() recomputes card size after a font change; .setText(value) replaces the sentence being flipped through. .pushProgress(value) feeds in a 0–1 scroll position from any custom source, exactly as real page scroll and hover-wheel input do internally - this is what the homepage's carousel card uses instead of the page scrolling to drive its Rolodex, and is the general escape hatch for tying the flip to anything other than the page or an element tagged data-rolodex-hover. With loopScroll on, values aren't clamped to 0–1 first, so a source that just keeps accumulating (like accumulated wheel delta) drives it around the loop repeatedly instead of pinning at either end. Rolodex.get(elOrSelector) / Rolodex.getAll(selector) look up already-initialized instances, and .destroy() tears one down (stops its animation loop and removes all listeners).
