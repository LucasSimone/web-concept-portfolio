Text Effect · Scroll + Continuous + Hover

Rolodex

Splits a sentence into words and shows them one at a time on a fixed-size 3D card that flips to the next word — either a two-flap "split-flap" display or a single-card front/back flip — as the user scrolls, on a timed loop in continuous mode, or, in "static scroll" mode, by scrolling with the page held still while hovering it.

Install

<script src="rolodex.js"></script>

Injects its own <style> tag covering the 3D card/flap/panel structure on first use, so no companion CSS file is required (the injected CSS hardcodes a white background on card faces). The downloaded file is self-contained - it bundles three small shared dependencies: hover-scroll-source.js ("static scroll" mode's wheel-target wiring), sequence-stepper.js (the animated-step engine behind 'continuous' driveMode and .next()/ .prev() below), and scroll-progress.js (the scroll-position math behind 'scroll' driveMode), all shared with Type Pan.

Quick Start

Reads data-text or trimmed textContent, splitting on whitespace into words. Auto-initializes against every .rolodex element — card size is measured via an offscreen canvas based on the widest word and computed font. This is all you need for the default scroll-driven split-flap: 

<div class="rolodex" data-text="Rolodex flips through words one by one">
  Rolodex flips through words one by one
</div>
<script src="rolodex.js"></script>

To configure it, call Rolodex.initAll yourself instead of relying on auto-init: 

Rolodex.initAll('.rolodex', {
  mode: 'split-flap',
  driveMode: 'continuous',
  flipWidth: 55,
  perspective: 900,
  shading: 0.05,
});

Recipes

Continuous autoplay

No scroll involved — the card flips through the sentence on its own timed loop, then rewinds and repeats. 

Rolodex.initAll('.rolodex', {
  driveMode: 'continuous',
  interval: 1400,      // ms held on each word
  flipDuration: 450,    // ms spent mid-flip
  rollbackSpeed: 900,   // ms to rewind last word -> first
});

Static scroll (hover-driven)

The element stays put on the page; wheel/trackpad input while hovering it drives the flip instead of scrolling the page. Point data-rolodex-hover at a wrapper if you want a bigger hover target than the card itself. 

<div id="wrap">
  <div class="rolodex" data-rolodex-hover="wrap"
       data-text="Hover and scroll to flip me">
    Hover and scroll to flip me
  </div>
</div>

<script>
  Rolodex.initAll('.rolodex', {
    driveMode: 'hover',
    hoverScrollDistance: 1000, // wheel delta to sweep the whole sentence
  });
</script>

Keep flipping once scroll goes idle

Stays scroll-driven while the user is actively scrolling, but picks up the continuous hold/flip/rewind loop from wherever it was left as soon as input stops — instead of just sitting there. 

Rolodex.initAll('.rolodex', {
  driveMode: 'scroll',
  loop: true,
});

Drive it from your own scroll position

Skip real page scroll entirely and feed progress in yourself — from a custom scroll container, a drag gesture, anything that produces a 0–1 (or, with loopScroll, unbounded) value. This is how the homepage carousel drives its card. 

const rolodex = new Rolodex(document.querySelector('.rolodex'), {
  driveMode: 'scroll',
});

myScrollSource.addEventListener('progress', (e) => {
  rolodex.pushProgress(e.value); // 0-1
});

Step through with buttons

.next()/.prev() work standalone, no scroll or hover source required. Set stepPolicy to control what happens if a button is clicked again before the current flip lands. 

const rolodex = Rolodex.get('.rolodex');

nextBtn.addEventListener('click', () => rolodex.next());
prevBtn.addEventListener('click', () => rolodex.prev());

Running more than one instance on a page, each with its own settings, is also simple — see Multiple Instances on the docs overview.

Options

OptionDefaultDescription
mode'split-flap'Visual style: 'split-flap' (two-flap card) or 'single-card' (simple front/back flip)
driveMode 'scroll'
  • 'scroll' — scroll position mapped across word segments
  • 'continuous' — self-animating hold/flip/rewind loop
  • 'hover' ("static scroll") — the element stays put on the page; wheel/trackpad input over it (or over an element tagged data-rolodex-hover="<that element's id>") drives the same scroll-position math as 'scroll' mode instead of scrolling the page
flipWidth55% of each word's segment spent mid-flip (the rest holds on a settled word)
perspective900CSS 3D perspective in px for the flip
shading0.550–1, how much a flap darkens as it turns edge-on
loopScrollfalseIn 'scroll'/'hover' driveMode only: makes the word list circular, so scrolling/wheeling past the last word flips straight on into the first (and past the first, back into the last) instead of stopping there. Independent of loop below - this is about active input continuing past the end, not what happens once input goes idle. Whatever feeds pushProgress() needs to pass values that aren't pre-clamped to 0–1 for this to have anything to work with (real page scroll can't - it's bounded by the page)
loopfalseIn 'scroll'/'hover' driveMode only: once input goes idle, keep flipping through the sentence on the same hold/flip/rollback clock 'continuous' mode uses (picking up from whichever word it was left on) instead of just holding there until input resumes
interval1400ms held on each word before flipping (continuous mode, or loop once idle)
flipDuration450ms spent mid-flip between words (continuous mode, or loop once idle)
rollbackSpeed900ms to rewind from the last word back to the first (continuous mode, or loop once idle)
hoverScrollDistance1000px-equivalent of wheel delta needed to sweep through the whole word list (hover mode)
scrollIdleDelay120ms of no scroll/wheel events before a fold-in-progress is treated as idle and settles instead of waiting for more input
snapStrength0.40–1, how fast the display catches up to scroll/hover position each frame - higher snaps almost instantly, lower lags behind and settles more slowly. Also governs the idle settle at the end of a fold. Try it live as "Catch-up speed" on the demo page.
stepPolicy 'redirect' What .next()/.prev()/.goTo() do if called again before the current flip lands - see the Methods section below.
  • 'redirect' — retargets immediately from wherever the flip visually is; a fast burst blurs past every word in between
  • 'rateLimit' — drops a call arriving less than minStepInterval after the last one accepted
  • 'queue' — lets the current flip finish, then plays queued calls back-to-back in order
minStepInterval450ms - only meaningful with stepPolicy: 'rateLimit'

Methods

MethodDescription
.next() / .prev() Flip forward or back one word, animated over flipDuration like a single 'continuous'-mode flip - never an instant jump.
.goTo(wordIndex, { duration }?) Flip directly to an arbitrary word, at the same per-word pace as a single flip by default (pass { duration } to use a fixed total time instead, regardless of distance). A multi-word jump visibly flips through every word in between rather than blurring past them.
.pushProgress(value) Feeds in a 0–1 scroll position from any custom source, exactly as real page scroll and hover-wheel input do internally - the general escape hatch for tying the flip to anything other than the page or an element tagged data-rolodex-hover. With loopScroll on, values aren't clamped to 0–1 first, so a source that just keeps accumulating (like accumulated wheel delta) drives it around the loop repeatedly instead of pinning at either end.
.remeasure() Recomputes card size after a font change.
.setText(value) Replaces the sentence being flipped through.
.destroy() Tears an instance down - stops its animation loop and removes all listeners.
Rolodex.get(elOrSelector) / Rolodex.getAll(selector) Static lookups for already-initialized instances, by element/selector.

.next(), .prev(), and .goTo() are intended for 'scroll'/'hover' driveMode, the same scope as .pushProgress() above: scrolling or wheeling again immediately takes back over from wherever the flip landed. What happens if one of them is called again before the last call finished is governed by stepPolicy above - worth trying out on the demo page, which has a Next/Prev button and a live Step policy switch.
