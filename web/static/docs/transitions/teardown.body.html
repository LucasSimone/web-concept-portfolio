Teardown

The page takes itself apart: on exit every element flies off the screen, the background last, until all that's left is a blank page. On the next page every piece starts off-screen and flies in, so the page builds itself. One continuous motion split across the navigation boundary, same shape as Shutter, Aperture, Static, Inkblot and Power Off, except that nothing is drawn over the page: the pieces are the page's own elements.

Install

<script src="teardown.js"></script>

Like the other transitions, this one belongs in <head> as a plain, non-async/defer tag, on every page that should take part. It has to run before the page paints, so an arriving page starts blank, with no flash of the finished page before it builds itself.

Dropping the script in doesn't intercept anything by itself: navigation is off until you set selector. With no config at all you still get play/cover/reveal for elements.

Quick Start

<script>
  window.TransitionConfig = {
    teardown: { selector: 'a[href]' },
  };
</script>
<script src="teardown.js"></script>

It now intercepts any left-click on a same-origin <a href> that isn't a hash link, a download link, a target="_blank" link, or opened with a modifier key held. The page tears down, then the browser navigates. The build-up only plays on the page that receives that navigation; a direct load, refresh or bookmark renders normally, and a destination that doesn't load teardown.js simply appears once the cover finishes.

How the Page Breaks Apart

At the start of every transition the script walks down from the target and decides, element by element, whether it flies as one piece or gets split into its children. grouping sets how far down that goes:

  • 'sections': anything smaller than about a third of the screen flies whole, so the page leaves in a few big blocks.
  • 'cards' (default): anything with its own background, border, shadow or ::before/::after flies whole, as do links and buttons. Plain wrappers are split, and so is anything covering more than half the screen, so a page wrapper with a background doesn't leave as one slab.
  • 'pieces': everything is split down to the elements that hold the content: headings, paragraphs, images, inputs.
  • 'words': like 'pieces', and blocks of text are split into their words too.

Images, video, canvases, SVGs and form controls are always one piece. A block of text (a paragraph with a link in it, say) flies as one piece unless the grouping is 'words' or it's marked data-teardown="split", and then it splits into its words. A few containers fly whole unless they're marked split, because their look can't be rebuilt from their parts: tables, lists with bullets or numbers, anything rotated, clipped, masked or filled with gradient text, web components with a shadow root, overlays (anything fixed, sticky or absolutely positioned with a z-index), and anything card-sized that clips its contents (a rounded card cropping its image), so nothing vanishes at its edge. The other way round, a box with a parallax (background-attachment: fixed) background, or with something inside using mix-blend-mode, is always split, so the background stays lined up until it leaves and the blend keeps blending with the page. Under 'words', a list item with a bullet or number, text cut short with an ellipsis or a line clamp, text in a right-to-left script, and text with an underline set on the whole block fly as whole blocks, and an underlined link inside a paragraph flies as one piece, so its underline goes with it.

A container that gets split still has its own background, border and shadow. Those are copied onto a stand-in behind the content that flies on its own, leaving after the last of the container's contents has gone and landing before the first of them arrives. The page's own background works the same way (see background), which is why every trip passes through a blank page in color.

Only what's on screen moves. Anything scrolled out of view is hidden for the length of the transition and put back afterward, as is anything the page's own scripts add while it runs, and every piece is hidden once it's gone. So a carousel that keeps turning, or a typing effect that keeps typing, can't bring anything back onto the blank page.

Recipes

Keep what both pages share

Teardown can't tell which parts of a page will still be there on the next one, but you can. Mark them data-teardown="keep" on both pages and they stay where they are while everything around them goes, then stay on screen from the first paint of the next page, so a shared header never blinks. A keep selector does the same from config. Kept elements win over grouping: anything holding one is split around it so it can stay behind. On an arriving page, what the last page kept and what this page keeps both count. 

<header class="site-header" data-teardown="keep">...</header>

<script>
  window.TransitionConfig = {
    teardown: { selector: 'a[href]', keep: '.site-header, #cookie-bar' },
  };
</script>

Hold something together, or take it apart

data-teardown="group" makes an element fly as one piece whatever the grouping; data-teardown="split" always breaks it into its children, even under 'cards' or 'sections'. 

<figure data-teardown="group">
  <img src="chart.png" alt="">
  <figcaption>Stays with its image</figcaption>
</figure>

<div class="panel" data-teardown="split">...</div>

Exempt a link from the transition

<a href="/elsewhere.html" data-no-transition>Skip the transition</a>

Override one link's look

A link can override any option for its own transition, leaving every other link on the page on the default profile. This is how the demo's controls panel changes only the Page One → Page Two link. The profile travels to the next page with the navigation, along with where the click landed, so the next page builds itself the same way the last one came apart. 

<a href="page-two.html" data-t-motion="throw" data-t-grouping="words" data-t-stagger="0.8">
  Enter Page Two
</a>

Set the page-wide default

<script>
  window.TransitionConfig = {
    teardown: {
      motion: 'spiral',
      direction: 'center',
      grouping: 'pieces',
      background: 'fade',
      scale: 0.4,
      selector: 'a[href]',
    },
  };
</script>
<script src="teardown.js"></script>

Element Transitions

Teardown can also transition any element in place: fly its contents out, swap them, then fly the new contents in. Mark the element class="t-el" and call play: 

<div class="t-el" id="card">...</div>

<script>
  Transitions.teardown.play(document.getElementById('card'), {
    from: event, // optional: where 'origin' is
    swap: (el) => { el.innerHTML = '<h3>New</h3><p>content</p>'; },
  });
</script>

play(el, options) covers el, calls options.swap(el) once it's empty (waiting on it if it returns a promise), then reveals whatever is there now. cover and reveal are public on their own for anything that doesn't fit that shape. All three take the same fields as the options below, plus from (a click event, an element, or { x, y } in viewport px), and return a promise that resolves when that step finishes.

The element itself is the stage: it stays put, its own background and border stay with it, and its contents are clipped to it while they fly, so they leave its edges rather than the screen's. background and color only apply to the page. Bare text sitting directly inside the element is wrapped for the length of the transition so it has a box to move. Anything swap adds stays hidden until reveal flies it in, even if swap takes a while.

Calling cover while a reveal is still running (or the other way round) turns the pieces around from wherever they've got to, over the matching share of the duration, rather than starting over.

Multiple Transitions

Teardown keeps its API, config and arrival flag under its own slug: window.Transitions.teardown, window.TransitionConfig.teardown, and a sessionStorage key of t-teardown-pending. So it loads alongside the other transitions without any of them clobbering the others. This site's own layout loads all six on every page, each reacting only to links tagged with its own slug: 

<script>
  window.TransitionConfig = {
    shutter:     { selector: '[data-t-transition="shutter"]' },
    aperture:    { selector: '[data-t-transition="aperture"]' },
    static:      { selector: '[data-t-transition="static"]' },
    inkblot:     { selector: '[data-t-transition="inkblot"]' },
    'power-off': { selector: '[data-t-transition="power-off"]' },
    teardown:    { selector: '[data-t-transition="teardown"]' },
  };
</script>
<script src="shutter.js"></script>
<script src="aperture.js"></script>
<script src="static.js"></script>
<script src="inkblot.js"></script>
<script src="power-off.js"></script>
<script src="teardown.js"></script>
<a href="/a" data-t-transition="inkblot">Uses Inkblot</a>
<a href="/b" data-t-transition="teardown">Uses Teardown</a>

The scripts don't coordinate. Arriving on the next page, each one only checks its own sessionStorage key, and only the clicked link's effect wrote one, so only that effect's reveal plays.

Methods

MethodDescription
configure(options) Merges options into the page-wide default profile, typically just to set selector from a script that runs after teardown.js.
cover(el, options) Flies everything in el (an element with class="t-el", or document.documentElement) off, resolving once it's empty. Leaves el torn down; pair with reveal().
reveal(el, options) Flies everything in el back in, resolving once it's landed and everything is put back. Called on an element that isn't torn down, it builds its current contents up from off-screen.
play(el, options) Covers el, runs options.swap(el) (may return a promise), then reveals.

Notes

Pieces are moved with the individual translate, rotate and scale properties, added to any the element already has, and any transform keeps applying on top. Nothing is written to a piece until it starts to move. The page's own CSS transitions are switched off on each piece while it flies, and every inline style the script touches is put back exactly as it was once the piece lands. An animation running on one of those three properties is held where it was for the length of the flight.

A piece inside a scrolling or overflow: hidden container (a carousel track, say) is clipped at that container's edge as it leaves, rather than flying across the screen. Splitting text into words leaves its text node where it was, emptied, with the words in spans beside it, so a framework holding on to that node can still write to it, insert next to it or remove it. If it does, that text is put back as it was at once and lands in place instead of flying. 'words' keeps every word on its line as it was, except that a very long word or URL can't break mid-word while it's split. Anything the page changes in a piece's inline style while it flies is kept when it lands. An element target gets an extra child (the layer its ghosts fly in) while it plays, which :last-child rules inside it will see.

Clicks, keys and scrolling are blocked while the page is tearing down or building up, including on an open dialog: every piece was measured where it sat, so the page can't move under it. Shortcuts with a modifier key still reach the browser. If the page is still there four seconds after it's torn down, the link didn't lead anywhere new (a download, an empty response, a cancelled "leave this page?"), and the page builds itself back. A slow server doesn't break the handoff: the next page builds in whenever it arrives. A link's referrerpolicy and rel="noreferrer" are kept. Respects prefers-reduced-motion: clicking a link navigates immediately, an arrival never builds up, and cover/reveal/play resolve straight away (play's swap still runs). A back/forward (bfcache) restore puts every torn-down target back together instead of replaying anything. Arrival is signalled with a short-lived sessionStorage entry, never anything in the URL.
