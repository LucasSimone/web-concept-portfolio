Power Off

An old CRT switching off: on exit the picture collapses from the top and bottom into a single bright line, the line pulls in to a glowing dot, and the dot fades out to a black screen. On the next page the set powers back on, playing the same motion in reverse until the picture fills the screen. One continuous motion split across the navigation boundary, same shape as Shutter, Aperture, Static and Inkblot.

Install

<script src="power-off.js"></script>

Like the other transitions, this one belongs in <head> as a plain, non-async/defer tag, on every page that should take part. It has to run before the page paints, so an arriving page starts on a switched-off screen with no flash of the page underneath.

Dropping the script in doesn't intercept anything by itself: navigation is off until you set selector. With no config at all you still get play/cover/reveal for elements. The slug has a hyphen, so the API is reached with brackets: Transitions['power-off'].

Quick Start

<script>
  window.TransitionConfig = {
    'power-off': { selector: 'a[href]' },
  };
</script>
<script src="power-off.js"></script>

It now intercepts any left-click on a same-origin <a href> that isn't a hash link, a download link, a target="_blank" link, or opened with a modifier key held. The screen switches off, then the browser navigates. The reveal only plays on the page that receives that navigation; a direct load, refresh or bookmark never shows the overlay, and a destination that doesn't load power-off.js simply appears once the cover finishes.

Recipes

Exempt a link from the transition

<a href="/elsewhere.html" data-no-transition>Skip the transition</a>

Override one link's look

A link can override any option for its own transition, leaving every other link on the page on the default profile. This is how the demo's controls panel changes only the Page One → Page Two link. The profile travels to the next page with the navigation, so it powers on in the same colors it switched off in. 

<a href="page-two.html" data-t-glow="#9fe8ff" data-t-duration="1400">
  Enter Page Two
</a>

Set the page-wide default

<script>
  window.TransitionConfig = {
    'power-off': { duration: 800, color: '#0b0f0b', glow: '#b6ffb0', selector: 'a[href]' },
  };
</script>
<script src="power-off.js"></script>

Element Transitions

Power Off can also transition any element in place: switch it off, swap what's inside, then power it back on. Mark the element class="t-el" (it gives the overlay something to size itself against) and call play: 

<div class="t-el" id="card">...</div>

<script>
  Transitions['power-off'].play(document.getElementById('card'), {
    swap: (el) => { el.textContent = 'New content'; },
  });
</script>

play(el, options) covers el, calls options.swap(el) once it's off (waiting on it if it returns a promise), then reveals. cover and reveal are public on their own for anything that doesn't fit that shape. All three take the same fields as the options below and return a promise that resolves when that step finishes. Every element keeps its own state, so several elements, or the same one called repeatedly, animate independently. The line and dot are sized from the element, so a small card gets a thin line and a small dot rather than the full-screen ones.

Calling cover while a reveal is still running (or the other way round) turns the motion around from wherever it's got to, over the matching share of the duration, rather than starting over.

Multiple Transitions

Power Off keeps its API, config and arrival flag under its own slug: window.Transitions['power-off'], window.TransitionConfig['power-off'], and a sessionStorage key of t-power-off-pending. So it loads alongside the other transitions without any of them clobbering the others. This site's own layout loads all six on every page, each reacting only to links tagged with its own slug: 

<script>
  window.TransitionConfig = {
    shutter:     { selector: '[data-t-transition="shutter"]' },
    aperture:    { selector: '[data-t-transition="aperture"]' },
    static:      { selector: '[data-t-transition="static"]' },
    inkblot:     { selector: '[data-t-transition="inkblot"]' },
    'power-off': { selector: '[data-t-transition="power-off"]' },
    teardown:    { selector: '[data-t-transition="teardown"]' },
  };
</script>
<script src="shutter.js"></script>
<script src="aperture.js"></script>
<script src="static.js"></script>
<script src="inkblot.js"></script>
<script src="power-off.js"></script>
<script src="teardown.js"></script>
<a href="/a" data-t-transition="static">Uses Static</a>
<a href="/b" data-t-transition="power-off">Uses Power Off</a>

The scripts don't coordinate. Arriving on the next page, each one only checks its own sessionStorage key, and only the clicked link's effect wrote one, so only that effect's reveal plays.

Options

OptionDefaultDescription
duration1000ms for each half (power off or power on) of the motion
easing'linear'Easing for the overall motion: linear, ease, ease-in, ease-out, ease-in-out or any cubic-bezier(). Each stage already has its own pacing, so linear is the natural look
color'#000'The switched-off screen. Any CSS color
glow'#fff'The line, the dot, and the light bleeding off them. Any CSS color
selectornull (off)Which links are intercepted. Navigation stays off until this is set

Methods

MethodDescription
configure(options) Merges options into the page-wide default profile, typically just to set selector from a script that runs after power-off.js.
cover(el, options) Switches el (an element with class="t-el", or document.documentElement) off, resolving once it's fully off. Leaves el covered; pair with reveal().
reveal(el, options) Powers el back on, resolving once it's fully revealed and cleaned up. Called on an element that isn't covered, it powers on from off.
play(el, options) Covers el, runs options.swap(el) (may return a promise), then reveals.

Notes

The overlay is a single element: the slot of screen still lit. A box-shadow with a huge spread paints the screen color everywhere outside it, a blurred shadow on top is the glow bleeding off the line, and a layer inside washes what's still showing toward the glow color as the slot narrows, so by the time it's a line it's pure light. Every frame is worked out from how far through the motion it is, so the fully covered frame is always just the screen color and the next page picks up from it exactly.

Respects prefers-reduced-motion: clicking a link navigates immediately with no cover, an arrival never plays a reveal, and cover/reveal/play resolve straight away (play's swap still runs). A back/forward (bfcache) restore resets every covered element instead of replaying anything. Arrival is signalled with a short-lived sessionStorage entry, never anything in the URL.

The overlay stacks above the target's own content, not the whole page. For the navigation case (covering <html>) that's the top of everything; for an element it's only as high as that element's stacking context allows.
