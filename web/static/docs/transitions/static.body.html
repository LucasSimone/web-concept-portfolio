Static

Old tube-TV channel noise: animated black-and-white static fades in to cover the screen on exit, keeps flickering the whole time it's covering the page (not just during the fade), then fades back out once the next page loads. One continuous motion split across the navigation boundary, same shape as Shutter and Aperture — just built from opacity and real per-pixel noise instead of a sliding panel or a spiraling iris.

Install

<script src="static.js"></script>

Like the other transitions, this one belongs in <head>, not next to the markup it affects — as a plain, non-async/defer tag, on every page that should take part. It has to run and register its CSS before the page paints, so the initial static (when arriving from another transitioned page) shows with no flash of the page underneath.

Dropping the script in doesn't intercept anything by itself: navigation is off until you set selector (see Options below). With no config at all, you still get Transitions.static.play/cover/reveal for transitioning elements — just no link interception.

Quick Start

Turn on navigation interception by setting selector before the script runs: 

<script>
  window.TransitionConfig = {
    static: { selector: 'a[href]' },
  };
</script>
<script src="static.js"></script>

No class to add and no elements to opt in beyond that — it now listens for clicks on the whole document and intercepts any left-click on a same-origin <a href> that isn't a hash link, a download link, a target="_blank" link, or opened with a modifier key held. Clicking one fades the screen into static, then navigates once it finishes. The reveal only plays on the page that receives that navigation — a direct load, refresh, or bookmarked visit never shows the overlay at all, and if the destination page doesn't also load static.js, the fade-in simply finishes and that page appears underneath with no reveal of its own.

Recipes

Exempt a link from the transition

Keep navigation on for the page but skip interception for one specific link, without removing the script. 

<a href="/elsewhere.html" data-no-transition>Skip the transition</a>

Override one link's timing or look

A single link can override duration, easing, tint color, grain, scanlines, scanline spacing, thickness, or edge blur for just its own transition, leaving every other link on the page using the default profile — this is how the demo's controls panel customizes only the Page One → Page Two link without touching the site nav around it. Whichever profile a click used — default or overridden — travels to the next page in the same handoff that triggers its reveal, so the two halves of the motion always match. 

<a href="page-two.html" data-t-duration="900" data-t-color="#3f0">
  Enter Page Two
</a>

Set the default timing, color, grain, or scanlines

Configure the page-wide profile once, alongside turning on selector: 

<script>
  window.TransitionConfig = {
    static: { duration: 700, color: '#ffb000', grain: 5, scanlineSpacing: 10, scanlineThickness: 4, scanlineBlur: true, selector: 'a[href]' },
  };
</script>
<script src="static.js"></script>

Reconfigure after the script has already loaded

Useful for widening or changing selector from a script that runs later, rather than setting window.TransitionConfig up front. 

Transitions.static.configure({ selector: '[data-t-transition="static"]' });

Element Transitions

Beyond whole-page navigation, Static can also transition any element in place — cover it, swap what's inside, then reveal — with no page load involved. Mark the element class="t-el" (gives the overlay a positioning context to size itself against) and call play: 

<div class="t-el" id="card">...</div>

<script>
  Transitions.static.play(document.getElementById('card'), {
    swap: (el) => { el.textContent = 'New content'; },
  });
</script>

play(el, options) covers el, calls options.swap(el) once it's fully covered (waiting on it first if it returns a promise), then reveals — one call for the common case. cover(el, options) and reveal(el, options) are also public on their own, for anything that doesn't fit that cover→swap→reveal shape (e.g. covering on one event and revealing on a separate later one). All three take the same fields as the per-link data-t-* attributes above, as a plain object, and return a promise that resolves once that step finishes — they're the primitives play is built from, not a separate flow. The noise keeps flickering for the entire time el stays covered, including however long swap itself takes.

Every element gets independent state: two different elements (or the same element called repeatedly, e.g. to loop it) each animate on their own, with nothing shared between them. 

// Two cards, two independent covers, at the same time.
Transitions.static.play(cardA);
Transitions.static.play(cardB);

// Looping the same element.
(function loop() { Transitions.static.play(card).then(loop); })();

Not part of the navigation flow above — a navigating page's cover has no same-document reveal to chain into (it navigates instead), so that flow uses cover/reveal directly rather than play.

Multiple Transitions

A page can load more than one transition effect at once, each handling a different set of links. Every effect keeps its public API, its config, and its arrival flag under its own slug — window.Transitions.static, window.TransitionConfig.static, and a sessionStorage key of t-static-pending — so a second, differently named effect's script can register alongside this one without either clobbering the other. This site's own layout does exactly that, loading Shutter and Aperture alongside Static on every page: 

<script>
  window.TransitionConfig = {
    shutter:  { selector: '[data-t-transition="shutter"]' },
    aperture: { selector: '[data-t-transition="aperture"]' },
    static:   { selector: '[data-t-transition="static"]' },
  };
</script>
<script src="shutter.js"></script>
<script src="aperture.js"></script>
<script src="static.js"></script>

Which link uses which effect is decided by the value of data-t-transition — each script only reacts to the name matching its own slug, so a given link can only ever belong to one effect: 

<a href="/a" data-t-transition="shutter">Uses Shutter</a>
<a href="/b" data-t-transition="static">Uses Static</a>

Neither script coordinates with the other. Arriving on the next page, each one only checks whether its own sessionStorage key was set — and since only one link is ever clicked at a time, only one key is ever written, so only that one effect's reveal plays.

Running the same effect configured differently in different places is a separate case that doesn't need any of this — see the per-link data-t-duration/ -easing/-color/-grain/ -scanlines/-scanline-spacing/ -scanline-thickness/-scanline-blur attributes above, which already let one script handle any number of differently configured links on one page.

That's a different multiplicity than Element Transitions' concurrent instances above — this section is about running different named effects (Shutter, Aperture, Static, …) on one page without them colliding; that one is about running this same effect on several elements (or the same element repeatedly) at once, which works because each target keeps its own independent state rather than sharing one page-wide profile.

Options

OptionDefaultDescription
duration1000ms for each half (fade in or fade out) of the motion
easing'ease-in-out'CSS easing applied to the opacity transition
color'#fff'Tint multiplied over the grayscale noise (like an old monochrome monitor's phosphor) — '#fff' leaves it untouched
grain2px per noise cell before the canvas is scaled up — bigger numbers mean blockier, more retro static
scanlinestrueOverlay faint horizontal CRT scanlines on top of the noise, scrolling slowly upward
scanlineSpacing5px between the start of one scanline and the next. Scroll speed stays constant (px/s) regardless of spacing, so wider spacing doesn't read as scrolling faster
scanlineThickness2px width of each scanline itself
scanlineBlurtrueFeathers each scanline's edges (1px in from either side) instead of a hard cutoff — at small scanlineThickness, the feather can consume the whole line
selectornull (off)Which links are eligible for interception — navigation stays off until this is set

Methods

MethodDescription
configure(options) Merges new options into the page-wide default profile - typically called just to widen/set selector from a script that runs after static.js has loaded.
cover(el, options) Fades el (an element with class="t-el", or document.documentElement) into full static, resolving once fully covered. Leaves el covered - pair with reveal().
reveal(el, options) Fades the static back out, resolving once el is fully revealed and cleaned up.
play(el, options) Sugar for "transition this element's content in place": covers el, runs options.swap(el) (may return a promise) once covered, then reveals. Not part of the navigation flow - that has no same-document reveal to chain into, so it uses cover/reveal directly instead.

All four are on Transitions.static. cover, reveal, and play take the same fields as the per-link data-t-* attributes above, as a plain options object, and return a promise that resolves once that step finishes.

Notes

Respects prefers-reduced-motion: with it set, clicking a link navigates immediately with no cover, and an arrival never plays a reveal; cover/reveal/play resolve immediately the same way — play's swap still runs, just with no static shown around it. A back/forward (bfcache) restore also skips replaying anything — pageshow with event.persisted resets every still-active element straight to its clean, uncovered state instead of replaying anything. Arrival state (for navigation) is tracked with a short-lived sessionStorage flag rather than anything in the URL, so it costs nothing to add and never shows up as a query param or hash.

Unlike Shutter's panels or Aperture's blades, which sit still once fully closed, the noise itself keeps flickering for the entire time a target stays covered — through the fade in, however long it takes for whatever it's covering to be ready (a page load, or a play() swap), and into the fade out — the same way a real dead channel never holds still.

The static overlay stacks above the target element's own content, not above the whole page — for the navigation case (covering <html>) that's already the top of everything, but for an element target it's only as high as that element's own stacking context allows. A descendant with its own higher z-index can still paint above it.
