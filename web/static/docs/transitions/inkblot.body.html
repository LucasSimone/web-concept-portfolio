Inkblot

Ink dropped on paper: a few drops land on exit, soak outward into ragged, bleeding blots, throw off small spatter, and merge into each other until the screen is solid ink. On the next page the same blots recede and dry away to reveal it. One continuous motion split across the navigation boundary, same shape as Shutter, Aperture and Static.

Install

<script src="inkblot.js"></script>

Like the other transitions, this one belongs in <head> as a plain, non-async/defer tag, on every page that should take part. It has to run before the page paints, so an arriving page starts under solid ink with no flash of the page underneath.

Dropping the script in doesn't intercept anything by itself: navigation is off until you set selector. With no config at all you still get Transitions.inkblot.play/cover/reveal for elements.

Quick Start

<script>
  window.TransitionConfig = {
    inkblot: { selector: 'a[href]' },
  };
</script>
<script src="inkblot.js"></script>

It now intercepts any left-click on a same-origin <a href> that isn't a hash link, a download link, a target="_blank" link, or opened with a modifier key held. The ink spreads, then the browser navigates. The reveal only plays on the page that receives that navigation; a direct load, refresh or bookmark never shows the overlay, and a destination that doesn't load inkblot.js simply appears once the cover finishes.

Recipes

Exempt a link from the transition

<a href="/elsewhere.html" data-no-transition>Skip the transition</a>

Override one link's look

A link can override any option for its own transition, leaving every other link on the page on the default profile. This is how the demo's controls panel changes only the Page One → Page Two link. The profile and the exact drops that link laid down travel to the next page with the navigation, so it recedes the blots the last page spread. 

<a href="page-two.html" data-t-style="rain" data-t-color="#1b2f8f">
  Enter Page Two
</a>

Set the page-wide default

<script>
  window.TransitionConfig = {
    inkblot: { duration: 1500, color: '#7a0d12', style: 'pool', bleed: 0.8, selector: 'a[href]' },
  };
</script>
<script src="inkblot.js"></script>

Styles

Where the drops land and how big they grow is the part meant to vary. style takes one of the built-in layouts:

  • 'splatter' (default): drops big drops spread across the target, landing early, each with a spray of spatter around it.
  • 'rain': five times as many medium drops, landing one after another.
  • 'pool': one drop in the middle that keeps spreading, ringed by the rest, so the cover closes from the center out.

Or a function that returns your own drops. It's called once per cover with the target's size and the profile, and returns an array of drops in px: 

Transitions.inkblot.play(card, {
  // A single row of drops falling left to right.
  style: ({ width, height, drops, splatter, random }) =>
    Array.from({ length: 8 }, (_, i) => ({
      x: (i + 0.5) * width / 8,
      y: height / 2 + (random() - 0.5) * height * 0.3,
      r: width / 7,
      at: i / 12,   // when in the cover it lands, 0–1
    })),
});
Drop fieldMeaning
x, yWhere it lands, in px from the target's top left
rThe radius it soaks out to, in px
atWhen in the cover it lands, 0–1. Optional, default 0
growHow much of the rest of the cover it spends spreading, 0–1. Optional: all of it for a big drop, a short burst for small spatter
lumpsHow many extra lobes to give its outline. Optional: a few for big drops, none or one for spatter. 0 gives a round drop

Drops don't have to cover the whole target: toward the end of the cover the ink floods the gaps left between them, starting at the edges of the blots around each one. The built-ins are on Transitions.inkblot.styles, so a custom style can call one and add to its result. A style that throws, or returns no drops, falls back to 'splatter'.

A function can't be written into a data-t-style attribute, so per-link styles are names only. A function set in TransitionConfig or passed to configure works for navigation too: the drops it produced are what travel to the next page, not the function.

Origin

Where the ink starts is its own option, so it works with every style, custom ones included:

  • 'scatter' (default): drops land wherever the style puts them.
  • 'cursor': the first drop lands where the click was, throwing spatter outward. The style's drops keep their places and sizes but land in order of distance from the click, so the ink runs outward across the page.
  • 'element': ink fills the pressed button or link almost at once, so it reads as bursting, then runs outward from there the same way.

For navigation the clicked link supplies both the point and the element. A link activated from the keyboard starts from its own center. For cover/play, pass the click as from: the event itself, an element, or { x, y, element } in viewport px: 

button.addEventListener('click', (event) => {
  Transitions.inkblot.play(panel, {
    origin: 'element',
    from: event,          // bursts out of the button, then across the panel
    swap: (el) => { el.innerHTML = nextPanel; },
  });
});

With no from, both fall back to scattering. If the pressed element is the target itself, there's no outline to burst from, so 'element' starts from the click point like 'cursor'. A custom style also gets the resolved origin as origin ({ x, y, rect } in the target's px, or null), though its drops are re-timed around it either way. On the next page the reveal recedes the same drops in reverse, so the ink drains back toward where it started.

Element Transitions

Inkblot can also transition any element in place: cover it, swap what's inside, then reveal. Mark the element class="t-el" (it gives the overlay something to size itself against) and call play: 

<div class="t-el" id="card">...</div>

<script>
  Transitions.inkblot.play(document.getElementById('card'), {
    swap: (el) => { el.textContent = 'New content'; },
  });
</script>

play(el, options) covers el, calls options.swap(el) once it's solid ink (waiting on it if it returns a promise), then reveals. Pass the click as from to start the ink there (see Origin). cover and reveal are public on their own for anything that doesn't fit that shape. All three take the same fields as the options below and return a promise that resolves when that step finishes. Every element keeps its own state, so several elements, or the same one called repeatedly, animate independently.

Calling cover while a reveal is still running (or the other way round) turns the same blots around from wherever they've got to, over the matching share of the duration, rather than starting over.

Multiple Transitions

Inkblot keeps its API, config and arrival flag under its own slug: window.Transitions.inkblot, window.TransitionConfig.inkblot, and a sessionStorage key of t-inkblot-pending. So it loads alongside Shutter, Aperture, Static, Power Off and Teardown without any of them clobbering the others. This site's own layout loads all six on every page, each reacting only to links tagged with its own slug: 

<script>
  window.TransitionConfig = {
    shutter:     { selector: '[data-t-transition="shutter"]' },
    aperture:    { selector: '[data-t-transition="aperture"]' },
    static:      { selector: '[data-t-transition="static"]' },
    inkblot:     { selector: '[data-t-transition="inkblot"]' },
    'power-off': { selector: '[data-t-transition="power-off"]' },
    teardown:    { selector: '[data-t-transition="teardown"]' },
  };
</script>
<script src="shutter.js"></script>
<script src="aperture.js"></script>
<script src="static.js"></script>
<script src="inkblot.js"></script>
<script src="power-off.js"></script>
<script src="teardown.js"></script>
<a href="/a" data-t-transition="static">Uses Static</a>

The scripts don't coordinate. Arriving on the next page, each one only checks its own sessionStorage key, and only the clicked link's effect wrote one, so only that effect's reveal plays.

Methods

MethodDescription
configure(options) Merges options into the page-wide default profile, typically just to set selector from a script that runs after inkblot.js.
cover(el, options) Spreads ink over el (an element with class="t-el", or document.documentElement), resolving once it's solid. Leaves el covered; pair with reveal().
reveal(el, options) Recedes the ink, resolving once el is fully revealed and cleaned up. Called on an element that isn't covered, it starts from solid ink with drops of its own.
play(el, options) Covers el, runs options.swap(el) (may return a promise), then reveals.
styles The built-in style functions, by name, for a custom style to build on.

Notes

The blots are a metaball field: each drop is a small cluster of overlapping circles, every circle adds a soft falloff to a low-resolution grid, and a cell is ink wherever the sum crosses a threshold. Summing is what makes nearby blots reach for each other and fuse, and the clusters give each drop a lobed outline. A fixed paper-grain texture roughens every edge so it wicks rather than expands, and the grid is smoothed up to full size, which softens it further. The grid is capped in size, so a full-screen overlay costs the same at any resolution.

Respects prefers-reduced-motion: clicking a link navigates immediately with no cover, an arrival never plays a reveal, and cover/reveal/play resolve straight away (play's swap still runs). A back/forward (bfcache) restore resets every covered element instead of replaying anything. Arrival is signalled with a short-lived sessionStorage entry, never anything in the URL.

The overlay stacks above the target's own content, not the whole page. For the navigation case (covering <html>) that's the top of everything; for an element it's only as high as that element's stacking context allows.
