Page Transition · Navigation

Aperture

A ring of camera-iris blades — curved panels seamed with lines, like a real diaphragm — spirals inward from the edge of the screen to the center when a link is clicked, their curved tips sealing shut at a point, then spirals back outward from that point once the next page loads, opening to reveal it. One continuous motion, split across the navigation boundary — the same shape as Shutter's rise/recede, but a twisting iris in place of a sliding panel.

Install

<script src="aperture.js"></script>

Like Shutter, this one belongs in <head>, not next to the markup it affects — as a plain, non-async/defer tag, on every page that should take part. It has to run and build its overlay before the page paints, so the initial sealed iris (when arriving from another transitioned page) shows with no flash of the page underneath. The overlay itself is a plain <div> appended straight onto <html> rather than <body> — it has to exist before <body> necessarily does, and a fixed-position element renders correctly regardless of where in the tree it sits.

Usage

There's no class to add and no elements to opt in — once it's on a page, it listens for clicks on the whole document and intercepts any left-click on a same-origin <a href> that isn't a hash link, a download link, a target="_blank" link, or opened with a modifier key held. Clicking one spirals the iris shut, then navigates once it finishes.

The reveal only plays on the page that receives that navigation — a direct load, refresh, or bookmarked visit never shows the overlay at all, and if the destination page doesn't also load aperture.js, the seal simply finishes and that page appears underneath with no reveal of its own. To exempt a specific link from interception without removing the script, add data-no-transition to it: 

<a href="/elsewhere.html" data-no-transition>Skip the transition</a>

To change the timing, colors, blade count, twist, or which links it watches, configure it before the script tag runs. Config and the script's own public API are both keyed by "aperture" rather than a shared name — see Multiple Transitions below for why: 

<script>
  window.PageTransitionConfig = {
    aperture: { duration: 800, color: '#eee', lineColor: '#111', blades: 6, selector: 'a[href]' },
  };
</script>
<script src="aperture.js"></script>

Or reconfigure it later, from any script that runs after aperture.js has loaded: 

PageTransitions.aperture.configure({ selector: '[data-pt-transition="aperture"]' });

A single link can override duration, easing, panel color, line color, blade count, or spin for just its own transition, leaving every other link on the page using the default profile — this is how the demo's controls panel customizes only the Page One → Page Two link without touching the site nav around it: 

<a href="page-two.html" data-pt-duration="900" data-pt-blades="5" data-pt-color="#000" data-pt-line-color="#fff">
  Enter Page Two
</a>

Whichever profile a click used — default or overridden — travels to the next page in the same handoff that triggers its reveal, so the two halves of the motion always match.

Multiple Transitions

A page can load more than one page-transition effect at once, each handling a different set of links. Every effect keeps its public API, its config, and its arrival flag under its own slug — window.PageTransitions.aperture, window.PageTransitionConfig.aperture, and a sessionStorage key of pt-aperture-pending — so it registers alongside Shutter without either clobbering the other. This site's own layout does exactly that: both scripts load on every page, each one reacting only to links tagged with its own slug: 

<script>
  window.PageTransitionConfig = {
    shutter:  { selector: '[data-pt-transition="shutter"]' },
    aperture: { selector: '[data-pt-transition="aperture"]' },
  };
</script>
<script src="shutter.js"></script>
<script src="aperture.js"></script>

Which link uses which effect is decided by the value of data-pt-transition — each script only reacts to the name matching its own slug, so a given link can only ever belong to one effect: 

<a href="/a" data-pt-transition="shutter">Uses Shutter</a>
<a href="/b" data-pt-transition="aperture">Uses Aperture</a>

Neither script coordinates with the other. Arriving on the next page, each one only checks whether its own sessionStorage key was set — and since only one link is ever clicked at a time, only one key is ever written, so only that one effect's reveal plays.

Running the same effect configured differently in different places is a separate case that doesn't need any of this — see the per-link data-pt-duration/ -easing/-color/-line-color/ -blades/-spin attributes above, which already let one script handle any number of differently configured links on one page.

Notes

Each blade is a real drawn shape, not a mask trick, and its two side edges are curves rather than straight spokes from the center — a real iris blade pivots around a point out near the rim, not the exact center, which is what makes its edges sweep tangentially as they run inward instead of radiating straight out. Two blades sharing a seam compute that shared curve from the same absolute angle so they always meet exactly, stroked in lineColor. The inner edge is a true circular arc, the same shape a real iris opening traces, filled in color. Their shared inner radius is driven by a single registered custom property, --pt-aperture-progress, which the browser transitions natively; a requestAnimationFrame loop just samples its live computed value every frame and rebuilds all the blade paths from it, since arbitrary path geometry can't be CSS-transitioned directly. At progress 0 every blade's inner edge collapses onto the center point, giving the sealed ring its curved triangular tips.

Respects prefers-reduced-motion: with it set, clicking a link navigates immediately with no seal, and an arrival never plays a reveal. A back/forward (bfcache) restore also skips replaying anything — pageshow with event.persisted resets straight to the clean, open state instead. Arrival state is tracked with a short-lived sessionStorage flag rather than anything in the URL, so it costs nothing to add and never shows up as a query param or hash.
