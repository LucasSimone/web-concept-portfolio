Page Transition · Navigation

Shutter

A full-screen black panel that rises from the bottom edge to cover the viewport when a link is clicked, then recedes back down to reveal the next page once it loads — one continuous vertical motion, split across the navigation boundary.

View Demo Download JS

Install

<script src="shutter.js"></script>

Unlike the other effects on this site, this one belongs in <head>, not next to the markup it affects — as a plain, non-async/defer tag, on every page that should take part. It has to run and register its CSS before the page paints, so the initial cover (when arriving from another transitioned page) shows with no flash of the page underneath.

Usage

There's no class to add and no elements to opt in — once it's on a page, it listens for clicks on the whole document and intercepts any left-click on a same-origin <a href> that isn't a hash link, a download link, a target="_blank" link, or opened with a modifier key held. Clicking one plays the exit cover, then navigates once it finishes.

The reveal only plays on the page that receives that navigation — a direct load, refresh, or bookmarked visit never shows the overlay at all, and if the destination page doesn't also load shutter.js, the cover simply finishes and that page appears underneath with no reveal of its own. To exempt a specific link from interception without removing the script, add data-no-transition to it: 

<a href="/elsewhere.html" data-no-transition>Skip the transition</a>

To change the timing, color, or which links it watches, configure it before the script tag runs. Config and the script's own public API are both keyed by "shutter" rather than a shared name — see Multiple Transitions below for why: 

<script>
  window.PageTransitionConfig = {
    shutter: { duration: 700, color: '#111', selector: 'a[href]' },
  };
</script>
<script src="shutter.js"></script>

Or reconfigure it later, from any script that runs after shutter.js has loaded: 

PageTransitions.shutter.configure({ selector: '[data-pt-transition="shutter"]' });

A single link can override duration, easing, or color for just its own transition, leaving every other link on the page using the default profile — this is how the demo's controls panel customizes only the Page One → Page Two link without touching the site nav around it: 

<a href="page-two.html" data-pt-duration="900" data-pt-color="#555">
  Enter Page Two
</a>

Whichever profile a click used — default or overridden — travels to the next page in the same handoff that triggers its reveal, so the two halves of the motion always match.

Multiple Transitions

A page can load more than one page-transition effect at once, each handling a different set of links. Every effect keeps its public API, its config, and its arrival flag under its own slug — window.PageTransitions.shutter, window.PageTransitionConfig.shutter, and a sessionStorage key of pt-shutter-pending — so a second, differently named effect's script can register alongside this one without either clobbering the other: 

<script>
  window.PageTransitionConfig = {
    shutter: { selector: '[data-pt-transition="shutter"]' },
    fade:    { selector: '[data-pt-transition="fade"]' },
  };
</script>
<script src="shutter.js"></script>
<script src="fade.js"></script>

(fade.js here just stands in for whatever second effect a site might run — this site currently only ships Shutter.) Which link uses which effect is decided by the value of data-pt-transition — each script only reacts to the name matching its own slug, so a given link can only ever belong to one effect: 

<a href="/a" data-pt-transition="shutter">Uses Shutter</a>
<a href="/b" data-pt-transition="fade">Uses the other effect</a>

Neither script coordinates with the other. Arriving on the next page, each one only checks whether its own sessionStorage key was set — and since only one link is ever clicked at a time, only one key is ever written, so only that one effect's reveal plays.

Running the same effect configured differently in different places is a separate case that doesn't need any of this — see the per-link data-pt-duration/ -easing/-color attributes above, which already let one script handle any number of differently configured links on one page.

Notes

Respects prefers-reduced-motion: with it set, clicking a link navigates immediately with no cover, and an arrival never plays a reveal. A back/forward (bfcache) restore also skips replaying anything — pageshow with event.persisted resets straight to the clean, uncovered state instead. Arrival state is tracked with a short-lived sessionStorage flag rather than anything in the URL, so it costs nothing to add and never shows up as a query param or hash.
