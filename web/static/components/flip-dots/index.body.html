Flip Dots

A programmable grid of physical discs. Each sits on a center axle: given a new state it makes a half turn, slams into its magnet stop, and swaps color at the moment it passes edge-on — which is how a two-faced disc holds any number of colors. Hover the board to flip single dots, or click one to send a ripple out from it.

Words, not just pixels

A board that says things

The same component with a 5×7 bitmap font over it. A message is one more whole-board update, so it arrives on a transition like anything else. Only the dots that differ between two messages flip, so swapping a word costs the handful of discs that disagree, not the board.

Any size

Same component, three scales

The grid is measured against the element's own box: give it a dotSize and the columns follow, give it cols and the dot size follows. Under about five pixels there is no room left for a disc to look like one, so a grid asked for finer than that gets thinned instead of drawn too small. Each board below reports what it actually got.

A live display

Driven by data

A clock, redrawn every second. Watch the minute roll over: only the discs in the digit that changed flip, and the rest of the board never twitches.

No transition on a tick — a clock that rippled every second would be a toy, not a clock.

Playback

A sequence, not a state

play() is a frame source plus a clock. The source is either an array of frames — a clip, like the one below — or a function the board asks for content on every beat, which is the live case. Frames are dropped, never queued: a disc can only make one half turn at a time, and a queue would let a fast source push the board further and further behind what it is meant to be showing.

Content sits on top

The canvas inserts itself as the element’s first child, behind everything else, so a board can carry content instead of only displaying it.
