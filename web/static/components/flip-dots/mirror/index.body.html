Mirror

The same component as the demo next door, playing your camera. Every frame the board asks a function for content, the function hands back the camera’s current frame as a grid of states, and a few thousand discs turn to meet it. Nothing here knows what a camera is — the board plays a sequence, and the sequence happens to be live.

The video never leaves this page. There is no upload, no recording and no server in this: the frame is drawn into a canvas, averaged down to the size of the grid, and thrown away. Stopping the camera releases it.

How it is wired

Six lines, and none of them are about cameras

play() takes either an array of frames or a function to ask for one. imageGrid() turns anything drawable — a <video>, an <img>, a canvas — into the same (x, y) => state accessor a hand-written pattern would be. Putting one inside the other is the whole of this page. 

const board = FlipDots.get('#board');

board.play(() => FlipDots.imageGrid(video, board.cols, board.rows, {
  levels: board.options.palette.length,
  mirror: true,
  autoLevels: true,
  dither: 'ordered',
}), { fps: 20 });

The grid is measured off the element’s own box, so the camera is resampled to whatever the board turned out to be rather than the other way round — change the dot size above and the next frame arrives at the new resolution with nothing to rewire.

Why ordered dither, by default, on a board

A two-color board has no grays, so the shades in between have to be traded for a pattern of dots whose density reads as the gray it replaced. Diffusion dithering does that better by every measure print cares about — until you remember that here, every dot that changes is a disc that physically turns. Diffusion carries each cell’s error into its neighbors, so one pixel moving in the corner of the frame shifts the answer everywhere after it, and a scene holding perfectly still still costs hundreds of flips a second. Ordered dither thresholds each cell against a fixed position, so a still scene produces an identical frame, and an identical frame flips nothing. Switch between them above and listen to how much more work the board is doing.

Live color — a palette lifted from the room

Every other palette here is a decision made in advance. Set it to Live color and the board stops working in shades of someone else’s colors and starts working in yours. FlipDots.imagePalette() clusters the frame down to the six colors actually in it, those become the board’s palette, and imageGrid’s match option sends every cell to the nearest one instead of to a step on a brightness ramp — so a disc is no longer light or dark, it is the color of whatever is in front of you. 

const palette = FlipDots.imagePalette(video, 6, { seed: board.options.palette });
board.update({ palette });

FlipDots.imageGrid(video, board.cols, board.rows, { match: palette });

The palette is re-clustered about once a second rather than every frame, seeded with the previous answer, and only adopted when a color has actually moved. All three are guarding the same thing, and it is the same thing the dither note above is about: a palette index is a dot’s state, so re-ordering the palette reassigns every disc on the board at once. Two clusters of nearly equal brightness will trade places on nothing more than sensor noise, which is a board that flickers once a second while the room holds perfectly still. Seeding keeps cluster six meaning cluster six; the deadband keeps a still room producing the identical palette, and an identical palette flips nothing.

The frame rate of a disc

The board plays at 20fps and its discs take 110ms each to turn, so frames land while the previous turn is still in the air. That is deliberate: a dot handed a new state mid-flight keeps its momentum and re-aims rather than restarting, so fast motion smears across the panel the way it would on a real one. Past that, asking for more frames does not buy more picture — it just means a larger share of the board never finishes a turn.
